# 修正记录

本文记录曾经形成错误行为或错误结论的问题，以及根因、修正和验证证据。普通代码改动不在此逐条记录。当前状态见 `STATUS.md`，实际运行见 `experiments/README.md`。

## C-001 PGMap 未设置限速被编码为有效限速

**发现日期**：2026-08-04  
**影响范围**：MetaDrive 程序化 `S`/`SC` 地图输入和闭环表现。

最初 `S` 和 `SC` 在约 1.7 s 时出界，一度被概括为 nuPlan 到 MetaDrive 的域偏移。实际 trace 显示，MetaDrive 用于表示“未设置”的 `1000 km/h` 被当成有效限速并转换为 `277.7778 m/s`，导致模型产生异常高速和横向偏移。

修正后，环境只替换精确的 `1000 km/h` 哨兵，保留已有真实限速；地图适配器再次拒绝残留哨兵。`SC` 中已有的 `20 km/h` 曲线 lane 不再被统一覆盖。

修正后的短闭环中，限速输入恢复正常，车辆无碰撞、未出界，轨迹速度回到合理范围。原始失败产物保留为错误接口对照，不能继续用于支持纯域偏移结论。

## C-002 运动学执行状态落后一个物理 tick

**发现日期**：2026-08-04  
**影响范围**：目标与实际轨迹误差、速度和加速度 trace。

旧执行器的可见状态系统性落后目标 waypoint，原因是目标状态写入时机与 MetaDrive 生命周期不一致。修正后，目标 world center 和 heading 在环境采样前写入，残留速度在下一物理阶段前清除，trace 增加逐点目标和误差。

回归结果显示位置和 heading 可逐点匹配。该证据只验证运动学执行时序，不验证低层 steering/throttle 跟踪。

## C-003 对早期出界原因的表述需要分层

早期出界首先由限速哨兵误编码造成，独立的执行时序错误又污染了轨迹误差。两项接口问题修正后，剩余表现才可用于讨论真实域差异。原始失败结果不得被概括为单一的模型域偏移。

## C-004 长路线审计拒绝曲线 lane 的 NumPy 标量

**发现日期**：2026-08-04  
**影响范围**：首次长时交通矩阵的混合路线。

路线审计只接受精确 Python 数值类型，而 MetaDrive 曲线 lane 的长度是有限的 NumPy 标量，导致合法路线在首次推理前失败。修正后接受 Python 和 NumPy 数值标量，同时继续拒绝布尔值、数组、非有限值和非正长度；新增对应回归测试。

首次失败目录继续保留，但不得视为完整矩阵。

## C-005 交通历史批量追加失败时留下部分状态

**发现日期**：2026-08-04  
**影响范围**：`MetaDriveObservationAdapter.append_frames()` 异常路径。

旧实现逐帧校验并立即写入历史。如果后续帧失败，前面已写入的帧不会回滚。修正后先验证整批帧，再一次性扩展历史；任何失败都保持原状态不变。

## C-006 矩阵汇总把合法空 diff 当作缺失产物

**发现日期**：2026-08-04  
**影响范围**：交通矩阵产物校验。

干净工作区中的 `tracked_diff.patch` 可以合法为空，旧汇总器却要求非空。修正后该文件必须存在但允许为空；其他配置、summary、trace 和可视化产物仍按各自契约校验。部分矩阵还必须是预定义网格的非空子集。

## C-007 长时交通失败不能解释为规划器缺乏基本驾驶能力

**修正日期**：2026-08-06  
**影响范围**：长路线交通矩阵的结论和后续评测设计。

已完成长时交通回合中，背景仿真车辆在持续运行后出现较为异常的行为，并进一步触发自车碰撞或出界。中程、低密度场景中规划器可正常行驶，因此长时矩阵不应被用于否定其基本驾驶能力。

修正后的解释为：

1. 长时矩阵可用于定位仿真交通稳定性和失败阶段；
2. 其中所有回合仍保留并按场景、时间阶段和终止类型标注；
3. 主要能耗评测改用短程或中程、较少背景车辆的稳定场景；
4. 场景只需覆盖巡航、过弯、变道、合流和限速变化等主要能耗因素；
5. 长时高交通量结果不得与稳定中程结果合并形成单一驾驶能力结论。
